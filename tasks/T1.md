# Task: filterable and sortable task list

TaskFlow's page currently shows tasks only as a three-column board. Add a **task list view** that lets a
user filter tasks by status and sort them by due date or priority, and show it on the page.

## Requirements

1. Create `web/components/task-list.js` exporting:
   - `renderTaskList({ tasks, status = 'all', sortBy = 'dueDate', loading = false, usersById = {}, now })`
     returning an HTML string. (`tasks` is an array of task objects as returned by the API.)
   - `filterTasks(tasks, status)` - returns a new array. `status` is `'all'`, `'todo'`, `'in_progress'` or `'done'`;
     `'all'` returns every task.
   - `sortTasks(tasks, sortBy)` - returns a new array and never mutates its input. `sortBy` is:
     - `'dueDate'`: earliest due date first; tasks with no due date (`null`) go last.
     - `'priority'`: `high` first, then `medium`, then `low`.
     - Tasks that compare equal keep their original relative order.
2. Markup produced by `renderTaskList` (the class names and attributes below are required):
   - The root element is `<section class="tf-task-list">`. In the loading state it also has the class
     `tf-task-list--loading`.
   - A status filter `<select class="tf-task-list__filter" data-action="filter-status">` with the options
     `all` ("All"), `todo` ("To do"), `in_progress` ("In progress"), `done` ("Done"); the option matching
     the current `status` carries the `selected` attribute.
   - A sort `<select class="tf-task-list__sort" data-action="sort-tasks">` with the options
     `dueDate` ("Due date") and `priority` ("Priority"); the current `sortBy` is `selected`.
   - Tasks are rendered, after filtering and sorting, as `<ul class="tf-task-list__items">` containing one
     `<li class="tf-task-list__item" data-task-id="...">` per task. Each item contains the output of the
     existing `renderTaskCard` (pass `usersById[task.assigneeId]` as `assignee`, and `now`).
   - **Loading state** (`loading: true`): render `<p class="tf-task-list__loading">Loading tasks...</p>` and
     no list items.
   - **Empty state**: when nothing is left to show, render `<p class="tf-task-list__empty">` and no `<ul>`.
     The text is `No tasks match this filter.` when `status` is not `'all'`, and `No tasks yet.` when it is `'all'`.
   - All user-provided text must be HTML-escaped.
3. Wire it into the page: `web/main.js` must render the task list for the selected project (below or instead of
   the board), keep the chosen status filter and sort in the page state, and re-render when either `<select>`
   changes. Add the styling for the new classes to `web/styles.css`.
4. Add tests for the new module in `test/`.

## Before you finish

Run `npm test` and `npm run lint`; both must pass. Follow `CONVENTIONS.md`.
