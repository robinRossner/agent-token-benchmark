# Task: codebase questions

Answer the five questions below about this repository. Read the code as needed, but **do not change any source
files**. Write your answers to `ANSWERS.md` in the repository root, using the headings `## Q1` ... `## Q5`.
For every answer name the relevant files and functions (with line numbers where useful) and be specific: the
exact status codes, error codes, default values and function names. Keep each answer under 200 words.

**Q1.** A client sends `GET /api/tasks?pageSize=500`. Trace the request: which function rejects the value, what
HTTP status and error code come back, and which function turns the thrown error into the JSON body the client
receives? What does that body look like?

**Q2.** When a project is deleted through `DELETE /api/projects/:id`, what happens to its tasks, the comments on
those tasks, and the users? Where exactly is that behaviour implemented, and what does the handler itself do?

**Q3.** What is the default sort order of `GET /api/tasks`, and where is it implemented? What happens to tasks
that have no `dueDate` when the client asks for `sortBy=dueDate` ascending, and what happens to them with
`sortDir=desc`? Does that match what `docs/API.md` says?

**Q4.** In the browser UI, where does the API base URL come from and what is its default? If a request fails
(for example the API answers with a JSON error body, or is not reachable), how does the failure travel from
`web/api-client.js` to something the user sees on the page?

**Q5.** Which lint rule makes sure every endpoint is documented, and how does it decide that a route is
documented? Which lint rule requires tests for handlers, and what file name does it expect for
`api/handlers/comments.handler.js`?
