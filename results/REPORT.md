# Do token-saving skills save tokens on coding tasks? Results

**Setup:** 45 Sonnet subagent runs = 5 arms × 6 tasks (+ a 2nd rep on T1, T2, T6), on a 59-file zero-dependency
Node repo (`fixtures/base`). Usage is summed per turn from each transcript (`scripts/usage.py`); cost uses Sonnet
API rates (cache write 3.75, cache read 0.30, output 15 $/MTok). Raw data: `runs.csv`, grades in `grades-*.md`.

| Arm | What it changes |
|---|---|
| baseline | nothing (commands via `rtk proxy` → raw output) |
| rtk | RTK hook condenses command output |
| caveman | caveman SKILL.md (terse prose) |
| ponytail | ponytail SKILL.md v5 (write the least code) |
| codemap | generated 98-line file map + "read the map first, no re-reads, use offset/grep" |

## Headline

| Arm | Cost vs baseline (geo-mean over 6 tasks) | Tokens | Turns | Output tokens | Code lines added* | Quality |
|---|---|---|---|---|---|---|
| baseline | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | all pass |
| rtk | 1.04 | 1.04 | 1.04 | 1.05 | 1.05 | all pass |
| caveman | 1.01 | 1.03 | 1.04 | 0.99 | 1.03 | all pass |

\* T1/T2/T6 feature tasks only (T3–T5 diffs are too small to compare).

**Only codemap saved tokens, and it did so on every task** (cost ratio 0.76–0.91 per task, with low spread between reps,
e.g. T6 $0.48/$0.49). The others are within noise: the same arm on the same task varied by up to 25% between reps
(baseline T6: $0.55 vs $0.69), so differences under ~15% mean nothing at this sample size.

## Quality: no arm got worse in a way that mattered
- Hidden tests: 44/45 runs passed everything. The miss: **codemap T5** fixed a broken seed reference by pointing task t_37 at
  the first project instead of restoring the original formula (`runs/codemap/T5/1/api/seed.js:50`). That plausibly comes
  from "read less": it didn't look at how the other tasks were assigned.
- T4 answers (0–5): caveman 5, everyone else 4.5 (all missed the same detail).
- T6 long-task adherence to CONVENTIONS (10-item checklist): **10/10 for every run in every arm**, so terse styles did not
  make agents drop constraints.

## What each skill actually does
- **codemap / lean reading:** cost is driven by **turns**. Every turn re-reads the agent's whole context (~45–50k tokens of
  system prompt + instructions before any work). A map that lets the agent go straight to the right files cut turns
  by about 22% and was the only lever that moved cost.
- **ponytail:** does what it claims for code. Its feature diffs were 13–35% smaller (T1 182 vs 246 lines, T2 96 vs 148, T6
  374 vs 432) with equal correctness, and output tokens fell 12%. But output is only ~13–37% of cost, and its "list
  every place your change must reach" step adds reading turns, so **net tokens were flat to slightly higher**. It's worth
  it for code size/maintainability on feature work; that could compound in complex projects (less code to read
  later), but this experiment can't show that.
- **caveman:** no measurable effect. Subagent output is mostly code and tool calls, not prose, so there was little for it to cut.
  It may help in chatty main-session conversations, which weren't measured here.
- **rtk:** no saving here (+4%). This repo's test/lint output is already short, so there was little to compress. It matches
  JetBrains' finding of no saving. It could still pay off on projects with huge build/test logs.

## Side observation
8 of 10 T2 runs also spotted and fixed the planted T3 pagination bug while adding the endpoint. Agents fix adjacent
bugs they see, regardless of arm.

## Caveats
- Small repo (59 files): navigation aids like codemap probably matter *more* on big repos; rtk too if logs are noisy.
- n = 1–2 per cell; Sonnet only; subagents, not long interactive sessions (where context bloat and output prose matter more).
- The codemap was pre-generated by a script (no token cost); in practice it must be kept up to date.
- Cost is API-rate equivalent; how cache reads count against a subscription's 5h window isn't public.

## What it cost
Setup (discovery + fixtures) ≈ $4.7, 45 runs ≈ $16.3, grading ≈ $0.8, so **≈ $22 at Sonnet API rates, ~29.5M tokens
(≈ 90% cache reads)**. Fixture building alone was $4.0.

## Recommendations
1. **Adopt a code map + lean-read rules** (a short `CODEMAP.md` or file map in CLAUDE.md, regenerated by script). It was the only clear win (~18% cost).
2. **Ponytail** if you want smaller diffs on feature work; don't expect token savings.
3. **rtk / caveman:** no benefit measured on this kind of work. Keep rtk only if your real projects produce long command output.
