# Do token-saving tools lower the cost of coding-agent tasks?

A small, controlled benchmark of four popular "token-saving" add-ons for coding agents (Claude Code), measured on the
same set of tasks with the same model. Question: does each tool reduce tokens and cost per task, without lowering
correctness?

## Setup

- **Model under test:** Claude Sonnet, for every run (one model only).
- **Arms (5):**
  - `baseline`: no add-on; shell commands run through `rtk proxy` so output is raw.
  - `rtk`: RTK hook condenses command output.
  - `caveman`: the caveman SKILL.md (terse prose), supplied as instructions.
  - `ponytail`: the ponytail SKILL.md v5 (write the least code), supplied as instructions.
  - `codemap`: a generated 98-line file map plus "read the map first, no re-reads, use offset/grep".
  See `arms/ARMS.md` for the exact brief snippets.
- **Tasks (6)** on a synthetic, zero-dependency Node repo (59 files, `fixtures/base`): T1 UI component, T2 backend
  endpoint, T3 bug fix, T4 code questions, T5 fix tests and lint, T6 long 8-step feature. Briefs are in `tasks/`.
- **Runs:** 45 subagent runs = 5 arms x 6 tasks, plus a second repetition on T1, T2 and T6.
- **Grading:** hidden tests in `fixtures/grading/` (agents never see them), the visible test suite and lint, a 10-item
  convention checklist for T6, and an answer key for T4. Usage is summed per turn from each run's transcript and priced at
  Sonnet API rates.

## Headline results

Cost relative to baseline (geometric mean over 6 tasks):

| Arm | Cost | Tokens | Turns | Output tokens | Quality |
|---|---|---|---|---|---|
| baseline | 1.00 | 1.00 | 1.00 | 1.00 | all pass |
| rtk | 1.04 | 1.04 | 1.04 | 1.05 | all pass |
| caveman | 1.01 | 1.03 | 1.04 | 0.99 | all pass |
| ponytail | 1.02 | 1.10 | 1.10 | 0.88 | all pass |
| codemap | 0.82 | 0.75 | 0.78 | 0.82 | 1 partial miss (T5, 6/7) |

Only the code map reduced cost, on every task (0.76 to 0.91 of baseline). The others were within noise; ponytail
produced smaller diffs (roughly 25% fewer added lines on feature tasks) but not fewer tokens. Full analysis, per-task
table and grading notes: `results/REPORT.md`.

## Limitations

- One model (Sonnet), one synthetic 59-file fixture; results may not transfer to large real codebases, where code maps
  and output compression could matter more.
- Small sample: 1 to 2 runs per cell. The same arm and task varied by up to ~25% between repetitions, so differences
  under ~15% should be read as noise.
- Runs were short subagent sessions, not long interactive ones, so effects on chat prose are barely tested.
- The code map was pre-generated by a script; keeping it current has a cost not measured here.
- Cost is API-rate equivalent, not subscription usage.
- Grading by the same people who designed the tasks; one grader pass, no inter-rater check.

## Reproduce

1. `scripts/new-run.sh <arm> <task> <rep>` creates `runs/<arm>/<task>/<rep>/` from `fixtures/base` (plus the task overlay
   and brief). Add the arm's snippet from `arms/ARMS.md` (and `.arm/` files from `arms/`) to the agent brief and run the
   agent in that directory.
2. `fixtures/grading/grade.sh <task> <run_dir>` runs the visible suite, lint and hidden tests; it prints one JSON line.
3. `scripts/usage.py label=<transcript.jsonl>` sums per-turn usage; `scripts/collect.py` builds `results/runs.csv`
   from run directories and transcripts.

The run directories (`runs/`) and raw agent transcripts are not published, and `collect.py` needs a mapping from runs to
transcripts that is also omitted, so the published CSVs are the record of the results. Fixtures need Node only.

## Layout

- `PLAN.md`: study design and budget.
- `research/DISCOVERY.md`: notes on candidate tools (summaries with links; vendor claims are not verified).
- `arms/`: arm definitions, the code-map generator and generated map, and the caveman and ponytail instruction files.
- `fixtures/`: base repo, per-task overlays, hidden grading tests.
- `tasks/`: task briefs T1 to T6.
- `scripts/`: run setup, usage extraction, aggregation.
- `results/`: `REPORT.md`, `runs.csv`, `results.csv`, grading notes.
