# Do token-saving tools lower the cost of coding-agent tasks?

A small benchmark of four popular "token-saving" add-ons for coding agents (Claude Code). Same tasks, same model, and
the question is whether each one cuts tokens and cost per task without hurting correctness.

## Setup

- **Model:** Claude Sonnet for every run.
- **Arms:** `baseline` (no add-on), `rtk` (hook that condenses command output), `caveman` (terse-prose SKILL.md),
  `ponytail` (write-the-least-code SKILL.md), `codemap` (a generated 98-line file map plus "read the map first, no
  re-reads"). Exact snippets are in `arms/ARMS.md`.
- **Tasks:** six, on a synthetic zero-dependency Node repo of 59 files: UI component, backend endpoint, bug fix, code
  questions, fix tests and lint, and a long 8-step feature. Briefs are in `tasks/`.
- **Runs:** 45 subagent runs, 5 arms x 6 tasks plus a second repetition on three of the tasks.
- **Grading:** hidden tests the agents never see, the visible tests and lint, a 10-item convention checklist for the long
  task, and an answer key for the questions. Usage is summed per turn from transcripts and priced at Sonnet API rates.

## Result

Cost relative to baseline, geometric mean over the 6 tasks:

| Arm | Cost | Tokens | Turns | Output tokens | Quality |
|---|---|---|---|---|---|
| baseline | 1.00 | 1.00 | 1.00 | 1.00 | all pass |
| rtk | 1.04 | 1.04 | 1.04 | 1.05 | all pass |
| caveman | 1.01 | 1.03 | 1.04 | 0.99 | all pass |
| ponytail | 1.02 | 1.10 | 1.10 | 0.88 | all pass |
| codemap | 0.82 | 0.75 | 0.78 | 0.82 | 1 partial miss (T5, 6/7) |

Only the code map saved anything, on every task (0.76 to 0.91 of baseline). The rest are within noise. Ponytail wrote
smaller diffs on feature tasks but not fewer tokens. Details, per-task numbers and grading notes are in
`results/REPORT.md`.

## Limitations

- One model, one small synthetic repo, 1 to 2 runs per cell. The same arm and task varied by up to 25% between
  repetitions, so differences under about 15% are noise. Large real codebases may behave differently.
- Short subagent sessions, not long interactive chats, so the effect on prose (caveman) is barely tested. The code map
  was generated by a script and its upkeep cost isn't counted.
- I designed the tasks and graded them myself, with a single grading pass.

## Reproduce

1. `scripts/new-run.sh <arm> <task> <rep>` sets up `runs/<arm>/<task>/<rep>/` from `fixtures/base`. Add the arm's snippet
   from `arms/ARMS.md` to the brief and run the agent in that directory.
2. `fixtures/grading/grade.sh <task> <run_dir>` runs the tests, lint and hidden tests and prints one JSON line.
3. `scripts/usage.py` sums per-turn usage from a transcript.

Raw run directories and transcripts are not published, so `scripts/collect.py` can't be re-run as is. The CSVs in
`results/` are the record. The fixtures need only Node.
